# 设计与架构说明（docs/design.md）

## 1. 核心评测哲学：纯粹剥离“单兵编码力”与“团队统帅力”

在传统软件工程基准中，强模型往往凭借自身超强的单文件编码能力一把梭通关，根本测不出它在担任**架构师 / 技术总监（Marshal）**时的组织拆解与质量把关水平。本基准通过三道物理机制彻底剥离单兵手艺：

1. **统一锁定真实弱模型执行者（`pi` Harness）**：底层全部工位统一驱动关闭深度思考档位的轻量级弱模型（复用 `speclock2` 的 `PiRpc` 常驻会话底座）。弱模型上下文一长必丢细节、缺少契约必写错跨模块签名。
2. **空白编制与物理视野隔离**：统帅最多创建 `5` 个工位，每个工位最多绑定 `4` 个具体 `.py` 文件。每次派单执行时，调度器为该工位生成仅包含其白名单文件与只读 `GLOBAL_CONTRACT.md` 的物理隔离工作台——工位既看不见其他模块的内部实现，也无法偷改他人领地的文件。
3. **物理禁手与反代写拦截**：主干 `workspace/` 空闲期施加操作系统只读属性并核对逐文件 SHA-256 清单；工单、契约、角色提示词与审查批注均经过源码代写检测，严禁统帅把现成代码塞进工单让弱模型照抄。

## 2. 五大反高分通胀设计铁律

1. **禁设预发验题机**：沙盒内的 `smoke_public.py` 仅检查启动与 1 条最基础建户提单连通路径，三波 30 项深层黑盒验收仅在 `finalize.py` 出榜阶段于隔离进程运行。
2. **禁直写、禁工单塞源码**：直写 `workspace/` 直接判作弊归零；工单连续超过 7 行可执行 Python 语句直接拦截并扣减 B1。
3. **重罚“1 个万能工人当传声筒”**：单工位最多绑定 4 个文件，且单工位运行在 C3 团队规模与分工均衡度子项直接计 `0` 分。
4. **效率分严格受终局交付率封顶**：`B1` 与 `B2` 均乘以 `A / 30`，杜绝草率派单秒退骗取耗时满分。
5. **盲评强制绑定 5 级平庸参照标尺**：每个盲评包自动内置 `REFERENCE_LEVEL5.md`，未明显超越传声筒式统帅的案例硬性锁死 `D <= 15 / 30`。
