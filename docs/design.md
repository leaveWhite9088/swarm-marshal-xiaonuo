# 设计与架构说明（docs/design.md）

## 1. 核心评测哲学：纯粹剥离“单兵编码力”与“团队统帅力”

在传统软件工程基准中，强模型往往凭借自身超强的单文件编码能力一把梭通关，根本测不出它在担任**架构师 / 技术总监（Marshal）**时的存量排雷、组织拆解、并行协同与质量把关水平。`xiaonuo-v2.0` 通过四道物理机制彻底剥离单兵手艺：

1. **存量暗雷半成品 + 二阶段紧急需求演进**：开局不再是空白骨架，而是一套约 900 行、默认跑通公开冒烟但深埋 6 处跨模块生产缺陷的半成品代码；一阶段排雷重构完成后，还必须解锁承接抢占补贴与母子共享授信池两项二阶段紧急需求。
2. **统一锁定真实弱模型执行者（`pi` Harness）**：底层全部工位统一驱动关闭深度思考档位的轻量级弱模型（复用 `speclock2` 的 `PiRpc` 进程隔离底座，并在系统临时沙盒中完全隔绝主干读写）。弱模型上下文一长必丢细节、缺少契约必写错跨模块签名。
3. **紧编制领地隔离与真实并行波次**：统帅最多创建 `3` 个工位，每个工位最多绑定 `3` 个互不重叠的 `.py` 文件。调度器内置跨进程可重入状态锁与并发波次扇出能力——契约正交解耦做得越好，越能让多工位同步并行推进、缩短关键路径墙钟耗时，彻底暴露“两工位空等一工位”的串行瓶颈。
4. **物理禁手、高信噪比限额与反代写拦截**：主干 `workspace/` 空闲期施加只读锁并核对逐文件 SHA-256 清单；全局契约上限 `5500` 字符、单张工单上限 `2000` 字符，且严禁夹带连续超过 7 行的现成业务源码。

## 2. 六大反高分通胀与防刷分设计铁律

1. **禁设预发验题机**：沙盒内的 `smoke_public.py` 仅检查启动与 1 条最基础连通路径（半成品开局即绿），四波 40 项深层跨模块黑盒压测仅在出榜阶段于隔离进程运行。
2. **选手域零过程指标剧透**：五大统领过程评价维度（侦察深度、并行波次率、负载均衡熵、审查零盲批与返工收敛率、关键路径耗时）仅存在于出榜计分器与盲评包中，严禁写入选手可见指令文档，防止清单式迎合刷分。
3. **禁直写、禁工单塞源码**：直写 `workspace/` 直接判作弊归零；工单塞现成源码直接拦截并扣减协同效率分。
4. **重罚传声筒与单点瓶颈**：单工位运行在团队分工子项直接计 `0` 分；同一工位连续串行超过 2 轮而闲置其余工位将触发串行瓶颈罚分。
5. **过程效率与纪律严格受交付率封顶**：协同与关键路径耗时分均乘以 `A / 25` 交付率系数，终局交付过低时架构过程分同步折算封顶，杜绝空转刷过程分。
6. **双锚点盲评硬锁顶**：盲评包内置 `[P01]–[P06]` 客观统领过程证据标签、5 级平庸参照标尺（未超越锁死 `<= 15.0 / 30`）与 9 级大师门槛（未达标锁死 `<= 25.0 / 30`）。
